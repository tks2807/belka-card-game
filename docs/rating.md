# Командный Elo

Для global_stats и chat_stats независимо используются средние рейтинги обеих пар:
`E = 1 / (1 + 10 ** ((loserAverage - winnerAverage) / 400))`,
`base = Math.round(K * (1 - E))`.

- K=32, если минимум `season_games_played` среди всех четырёх игроков до матча <10; иначе K=24. Условие проверяется отдельно в каждой области.
- Каждый победитель получает `base + (голая ? 15 : 0) + личный бонус серии`.
- Личный бонус равен +3 на третьей и каждой последующей победе подряд: сохранённая серия **до** матча >=2. Он не растёт с длиной серии.
- Проигравшие теряют только `base`, без дополнительных штрафов за голую или серию.
- Итоговый рейтинг ограничивается диапазоном 500..9999. Возвращаемые изменения относятся к чату и отражают фактическую разницу после ограничения.

## Серия и транзакция

Источник серии — существующий `player_chat_features.win_streak` **текущего чата**.
Этот же личный бонус применяется и к глобальному, и к чатному Elo; новой глобальной серии и миграции схемы нет. Победы в другом чате не продолжают серию этого чата.

`updateTeamRatings` создаёт отсутствующие строки features с нулевыми значениями через `ON CONFLICT DO NOTHING`, затем читает рейтинги и серии с `FOR UPDATE` внутри одной транзакции до записи рейтингов. Метод не увеличивает и не сбрасывает серию.
Единственный существующий владелец изменения серии — последующий `updatePlayerStats(..., countGame=true)`: победа +1, поражение 0. При `countGame=false` серия не меняется.

Существующее ограничение: транзакция рейтингов и последующие обновления статистики отдельных игроков не атомарны как единый матч. Ошибка после фиксации рейтингов может оставить старую серию/частичную статистику. Блокировки снимка не обеспечивают идемпотентность повторного завершения матча или сериализацию всего жизненного цикла между этими транзакциями. Здесь эта архитектура не менялась.

## Проверка без БД

`npm run test:rating` собирает проект и запускает Node tests реального StatsService с транзакционным in-memory mock клиента SQL. DB-модуль подменяется до импорта сервиса: учётные данные и реальная БД не загружаются. Проверяются граница калибровки, рейтинги пар, независимость областей, бонусы, жизненный цикл серии, SQL-контракт блокировок, ограничения и rollback при ошибках чтения/записи. Реальная конкурентность PostgreSQL этими mock-тестами не проверяется.
